# 设计与限制

## 权威状态来自执行结果

模型通过 `Decision` 提议调用。注册表检查输入并计算指纹，策略检查依赖和授权，执行器产生 `ToolResult`，观察阶段再更新 `AgentState`。文字回答与结构化评价分开保存。

模型、反思器及经验存储回调收到状态副本；修改副本不能直接改变当前任务的权威状态。Python 扩展仍是受信代码，不具备进程隔离。

## 运行边界

每次 `run` 都是新任务。`max_steps` 是模型决策预算，每次最多 8 个调用；超过 8 个的整批被拒绝。调用 ID 在一次运行内不得复用。多调用响应按序逐个门控，防止沿用调用前的过期证据。

| `stop_reason` | 含义 |
| --- | --- |
| `completed` | 模型返回不带工具调用的决定 |
| `max_steps` | 用完模型决策预算 |
| `model_error` | 模型回调异常 |
| `invalid_decision` | 模型返回不符合决定契约 |
| `too_many_tool_calls` | 单次决定超过 8 个调用 |

`completed` 不是任务正确性或评价通过的证明。应根据所需的证据和工具评价判断业务目标是否满足。

预算限制流程继续发起工作的次数，不会中断正在运行的处理函数。应用需要为网络请求、子进程和长计算单独配置超时与取消。

## 授权寿命与恢复

授权精确绑定任务、上下文、工具名称与参数指纹；在调用处理函数前消耗。同一策略实例保留已消耗记录。授权不从对话或检索内容推断。

这里没有跨进程授权重放账本，也不提供持久化“恰好一次”外部执行保证。状态快照用于检查和保存，不会自动恢复未完成动作。进程在远端动作发生后崩溃时，应由应用查询远端结果并处理未知状态。

## 经验与数据

内存和 SQLite 存储具有相同的上下文筛选与去重规则。记录按任务、上下文和调用 ID 去重；再次记录同一事件不会覆盖原有记录。经验中不注入工具原始数据或 artifact 文件内容，但目标和反思文本本身可能包含敏感信息。

`context_id` 是检索命名空间，不是身份认证边界。SQLite 没有内置加密或租户访问控制。调用方负责存储路径、访问权限、备份与清理。

## 当前验证能说明什么

测试证明所覆盖输入下的框架行为，离线演示说明组件连接方式。它们没有测量实际模型的成功率、跨领域泛化、检索收益、生产吞吐或实机可靠性。新增应用应提供自己的数据、评价器与对照实验。
